# تسليم منظومة التوزيع المفتوح والإلغاء في تمريضي

هذه حزمة تطوير محلية قابلة للمراجعة. يبقى التوزيع بالموجات للطلبات الحالية، وللطلبات الجديدة ما لم يُفعّل مفتاحا السياسة. إطلاق التوزيع المفتوح موقوف على التحقق الميداني واعتماد إعدادات التشغيل.

## المعمارية

- يحفظ الطلب المفتوح لحظة بداية واحدة وموعد انتهاء واحدًا وسياسة الأهلية. يوزع العامل العرض على المؤهلين في النطاق دون سقف عددي. تسرّع أحداث الأهلية تشغيل وظيفة الطلب، وتلتقط المصالحة الدورية الأحداث التي فاتت أثناء القفل أو الانقطاع.
- يؤكد PostgreSQL الإسناد تحت قفل الطلب والممرض والعرض. التحقق من انتهاء العرض والأهلية يجري على الخادم. يعيد القبول المكرر الإسناد الذي ثبت، حتى لو انتقلت الزيارة بعدها إلى مرحلة أخرى.
- انطلاق الممرض خطوة صريحة. يطلب الخادم مسار القيادة خارج المعاملة، ويتحقق من مرجع بيانات الموقع داخلها، ثم يثبت مدة السفر والموعد المرجعي. غياب التقدير الموثوق يترك الحالة `ETA_UNAVAILABLE`.
- الإلغاء يسجّل واقعة واحدة ومفتاح إعادة محاولة وأثر الالتزام ضمن المعاملة. الإلغاء قبل الانطلاق دون أثر سلبي. الإلغاء أثناء الطريق يحتاج إقرارًا عندما توجد أدلة صالحة ولم تُتجاوز العتبة. عند مرور 30 دقيقة من موعد الوصول المرجعي يكون الإلغاء معذورًا. لا رسوم إلغاء.
- الاعتراض المفتوح يعلق الأثر في الملخص. قبول الاعتراض يزيل الأثر الحالي ويحفظ التصنيف السابق وهوية المراجع، ويظل رد إعادة محاولة الإلغاء مطابقًا للقرار الأصلي.
- حجز أحداث Push وSocket.IO وإعادة المحاولات مستقل في قاعدة البيانات. لا يحتفظ العامل بقفل قاعدة البيانات أثناء الاتصال بالمزوّد. الإغلاق يحدد العرض المقصود، وتتحقق المصالحة في التطبيق من العروض المفتوحة.

## قاعدة البيانات

| الترحيل | الأثر |
| --- | --- |
| 021 | نافذة البحث والإغلاق ومرجع ETA، وأربعة جداول للإلغاء والاعتراض وسجلّي انتقالاتهما. قيود التكرار والأثر الزمني ومرجع الإسناد، وفهارس نافذة البحث والالتزام والمراجعة. |
| 022 | حفظ حدود حداثة النبض والموقع ودقته للطلب، ومحفزات إيقاظ وظيفة البحث عند تغيّر التوفر أو المؤهلات أو الموقع أو التسوية. |
| 023 | حجوزات قصيرة قابلة للاستعادة لعاملَي التحديث الفوري وFirebase وإعادة محاولة الجهاز. |
| 024 | مهلة انطلاق اختيارية وطابع إرسال التذكير وفهرس جزئي للتذكيرات المستحقة. صفر يعطّل التذكير. |

تستمر قيود الإسناد النشط الفريد لكل طلب ولكل ممرض. لا يوجد ملء رجعي لموقع أو ETA أو عقوبة تاريخية. يوضح [دليل الترحيل](MIGRATION_021.md) الفحص المسبق وخطوات الرجوع التشغيلي.

## عقد الـ API

| المسار | التغيير |
| --- | --- |
| `POST /v1/requests` | يعيد مواعيد نافذة البحث عندما تُفعّل السياسة. |
| `GET /v1/requests/:id/cancellation-policy` | يعرض إمكانية الإلغاء وتصنيف المعاينة ورقم إصدار الحالة. |
| `POST /v1/requests/:id/cancel` | يدعم `CancelRequestDto` للسبب والإقرار والإصدار ومفتاح إعادة المحاولة. الطلب القديم بلا DTO لا ينتج أثرًا سلبيًا. |
| `GET /v1/me/commitment` | سجل المريض وملخص الإلغاءات. |
| `GET /v1/nurse/offers/:id/commitment` | إحصائية مجرّدة لمالك عرض مفتوح صالح، مع حد أدنى للعرض. |
| `POST /v1/cancellations/:id/appeals` | تقديم اعتراض لمالك الواقعة المؤهلة داخل المهلة. |
| `GET /v1/me/cancellation-appeals` | قائمة الاعتراضات الخاصة بالمستخدم. |
| `GET /v1/admin/cancellation-appeals` | قائمة المراجعة الإدارية. |
| `POST /v1/admin/cancellation-appeals/:id/review` | انتقال موثق باستخدام `ReviewAppealDto`. |
| `GET /v1/nurse/me/offers` | توقيت الخادم للعداد ومسافة تقريبية، مع حجب عنوان الزيارة قبل الإسناد. |

## التطبيقان ولوحة الإدارة

واجهة المريض تميز الإسناد عن الانطلاق وتعرض نافذة إلغاء Aero والإقرار أو الاعتذار حسب معاينة الخادم، مع شاشة سجل الالتزام وتقديم الاعتراض. يحتفظ تطبيق الممرض بتصميم العرض، ويعرض الملخص وحده ويطلب بدء التوجه بزر منفصل. عند إلغاء مهمة قائمة يتوقف التتبع وتُزال الوجهة عند المصالحة. تعرض لوحة الإدارة إعدادات التوزيع والتذكير وقائمة مراجعة الاعتراضات وعدد مهام الانطلاق المتأخرة.

## الخصوصية وأدلة التحقق

- العنوان والنص الحر وأسباب الإلغاء الصحية خارج عرض الممرض وحمولة الإغلاق. يظهر للممرض عدد الزيارات والإلغاءات في نافذة محدودة عند توفر عينة كافية. اعتماد القرار الإحصائي لا يؤثر تلقائيًا على أهلية المريض للرعاية.
- أثبتت الاختبارات المحلية 100 عرض في الدفعة الأولى وانضمام ممرض إضافي دون تمديد أو تكرار، مع رفض إنشاء عرض بعد انتهاء البحث. اختُبرت حدود +29:59 و+30:00 و+30:01 في قيد قاعدة البيانات.
- غطّت الاختبارات انتهاء العرض، وإعادة القبول، وتثبيت ETA خارج اتصال المزود، وتذكير الانطلاق مرة واحدة، وتطابق إعادة الإلغاء، وتعليق أثر الاعتراض وقبوله، وحجب المعلومات الخاصة.
- اختُبرت استعادة حجز عامل منتهي. قبول FCM في الاختبارات أو تسجيل حالة SENT لا يثبت وصول الجهاز. يبقى التسليم الخارجي قابلًا للتكرار إذا توقف العامل بعد قبول المزود وقبل تسجيله.
- فحص 100 عرض اختبار وظيفة على PGlite بمسافة بديلة. لا توجد قياسات PostGIS ممثلة للحمل أو قيم P50/P95/P99 معتمدة.

## بوابات الإطلاق

- شغّل اختباري التزامن على قاعدة PostgreSQL/PostGIS منفصلة وقابلة للتخلص منها عبر `TEST_DATABASE_URL`. اختبر منافسة عشرة ممرضين وقبولًا متزامنًا مع الإلغاء، ثم استكمل مصفوفة السيناريوهات المطلوبة.
- افحص خطط `EXPLAIN (ANALYZE, BUFFERS)` على بيانات مرحلية ممثلة. جرّب Push وإغلاق الإنذار في الخلفية وعلى شاشة مقفلة على هاتف فعلي مع Firebase المرحلية.
- المتبقي في المنتج يشمل معالجة ما بعد الوصول والإنهاء المبكر وفق سياسة منفصلة، وواجهة اعتراض الممرض كاملة، والمرفقات المحمية، وتقارير الاستبعاد المفصّلة للنطاق المفتوح والقياس الإنتاجي. لا يحدث إلغاء عادي بعد الوصول أو بدء الخدمة.
- راجع نسخ قاعدة البيانات والاستعادة والنافذة التشغيلية للترحيل، واعتمد إعدادات الأهلية والمُهل قبل تشغيل السياسة. يتطلب التفعيل موافقة على الإصدار واختيار `OPEN_DISPATCH_ENABLED=true` و`dispatch.openEnabled=true`. لم يُنشر الفرع إلى الإنتاج.
