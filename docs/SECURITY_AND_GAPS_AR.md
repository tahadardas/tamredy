# ضوابط الأمان والفجوات الحالية — إلزامية قبل النشر

## منع الإسناد المزدوج
- `requests.service.create`: يحجز مفتاح idempotency لكل مستخدم ضمن نفس المعاملة قبل إنشاء الطلب.
- `dispatch.service.accept`: يقرأ معرف العرض، ثم يقفل الطلب، ثم الممرض، ثم العرض داخل Transaction، ويتأكد من التأهيل والتوفر، ثم يغلق بقية العروض.
- `001_core.sql`: فهرسان جزئيان يفرضان `UNIQUE` على `(request_id)` و`(nurse_id)` للإسنادات النشطة.
- انتهاء العرض أو تغير حالة الطلب يجب أن ينتج 409/410، وليس قبولًا محليًا.

## مخاطر تحتاج معالجة قبل التشغيل
- سلسلة JWT الحالية تعتمد سرًا متماثلًا مهيأ بالبيئة ولا تحتوي تدفق OTP أو إعادة إصدار رموز أو توقيع مفاتيح دوّارة. إنتاج: ادعم auth module كاملًا وMFA وسجلات الجلسات.
- معدل إنشاء الطلب وRate Limits والتحقق من الأرقام والهوية والخصوصية لم يُدمج بعد. يجب استخدام API gateway / Nest throttler + مكافحة السبام.
- يحتاج المريض تأكيد العنوان والتصريح بأنه ليس طلب طوارئ، لكن ذلك لا يعوض فرزًا سريريًا مهنيًا للحالات.
- لا تقرأ من `care_requests` للعميل دون التحقق من ملكية الطلب؛ الممرض لا يرى العنوان الدقيق إلا بعد إسناده.
- الاحتفاظ المستمر بمواقع GPS قد يكون غير قانوني؛ يجب اعتماد سياسة تقليل البيانات والإلغاء التلقائي لأذونات المشاركة.
- توجد ثغرة أعمال معروفة: التعامل مع اعتذار الممرض بعد قبول الطلب، والعودة لإعادة التوزيع، وحالات النزاع وno-show ليست مكتملة.
- P95 والتوافر واختبارات البنية ليست محسومة. أرقام المواصفات أهداف وليست قياسات.
- آلية نشر Redis PubSub best effort؛ بعد عودة الاتصال يجب استعلام REST، ولا يعتمد قبول على Socket.IO.
- لا توجد تحويلات بنكية ولا رصيد محفظة. لا تنشئ نقدًا رقميًا دون جهة مرخصة.
- يجب إضافة توقيع Webhook ومطابقة دفتر الحسابات مزدوج القيد بشكل ذرّي قبل فتح الدفع.
- ينبغي وضع تشفير مناسب لملفات المرضى وإجراءات موافقات وعزل سجلات حسب النوع قبل تخزين أي تفاصيل طبية.
- `dev-seed` يُنشئ بيانات زائفة ورخصة وهمية، ويُحظر تشغيله تمامًا خارج localhost/التطوير.
- حماية CORS ليست بديلًا عن المصادقة. أوقف جميع إعدادات التطوير قبل الإنتاج.

## جودة الشيفرة وحالة التحقق
في بيئة إنشاء الحزمة لا يمكن الوصول إلى npm registry أو تثبيت Docker/PostgreSQL/Flutter؛ ولذلك تم تنفيذ اختبار TypeScript domain فقط. ما زالت بحاجة إلى `pnpm install` و`pnpm typecheck` واختبارات وحدة وتكامل كاملة. لا يجوز اعتبار نجاح `node --test` بمثابة اعتماد إنتاجي.
