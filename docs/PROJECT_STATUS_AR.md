# حالة المشروع — تحليل ومتابعة التنفيذ (21 نوفمبر 2026)

## أين وصل المشروع قبل هذه الجلسة (v0.2)
- **الخلفية (NestJS + PostgreSQL/PostGIS + Worker):** قبول ذري للطلبات، موجات توزيع 3/6/10 كم، Keyset pagination، Redis cache — مكتوبة لكن **غير مشغَّلة** (لا PostgreSQL/Redis في بيئة الإنشاء).
- **التطبيقات:** هياكل Flutter عامة لا تطابق التصاميم المرجعية (27 شاشة)؛ لوحة إدارة React تأسيسية بـ6 تبويبات.
- **غير منجز (حسب SRS وNEXT_SPRINT):** OTP/JWT حقيقي، توثيق الممرضين، FCM، المحاسبة والمحفظة، النزاعات، اختبارات التكامل.

## تحديث v0.5 — الحسابات اليدوية، FCM، إعادة الاتصال
- **OTP مُعطَّل مؤقتًا** (`AUTH_MODE=password` افتراضيًا): نقاط OTP تعيد 404. يُعاد تفعيله في آخر مرحلة بـ`AUTH_MODE=otp` + مزود SMS.
- **الحسابات من لوحة الإدارة:** صفحة «الحسابات» (تسجيل مريض/ممرض، إيقاف/تفعيل، إعادة كلمة المرور). كلمات المرور تُخزَّن scrypt وتُعرض مرة واحدة. **أول مشرف:** `ADMIN_PHONE=+... ADMIN_PASSWORD=... node apps/api/scripts/create-admin.mjs` بعد البناء والترحيل.
- **FCM (خادم):** `device_tokens` + `POST /v1/devices`؛ الـWorker يرسل بعد نشر الـoutbox برسائل بلا بيانات شخصية، يحذف الرموز الميتة، ولا يعطّل الـoutbox عند الفشل. يتطلب `FCM_SERVICE_ACCOUNT_JSON`.
- **الأجهزة:** `RealtimeHost` في `flutter_core`: Socket.IO بإعادة اتصال تلقائية، تجديد الرمز عند رفض الخادم، مزامنة REST عند كل اتصال/استئناف/إشعار، وتسجيل FCM (`--dart-define=FCM_ENABLED=true` بعد إضافة google-services.json / GoogleService-Info.plist).
- **التحقق:** اختبارات API 14/14 (OTP + حسابات)، Worker/FCM 4/4 بـfetch مُحاكى، Flutter analyze/tests تنجح.
- **لم يُختبر:** إرسال FCM الفعلي، اتصال Socket.IO الحقيقي (يحتاج Redis+Postgres)، تشغيل على جهاز. ملفات Firebase للمنصات غير موجودة (حساب مشروعك مطلوب).
- **أمني:** الدخول بكلمة مرور لحسابات الإدارة دون MFA — للتجربة الداخلية فقط، لا تعرض الخادم للإنترنت.
