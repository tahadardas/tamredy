# تثبيت تمريضي والتحقق من الإصدار

فرع العمل `feature/tamreedy-core-stabilization` مبني على `af3feb4`. بقيت التطبيقات والخادم في حزمها الأصلية. التغييرات قابلة للمراجعة مستقلًا عن فرع إعادة التصميم. لم تُطبّق على بيانات إنتاج.

## التغييرات وعقود التكامل

| المجال | الملفات الرئيسية | العقد |
| --- | --- | --- |
| دورة الطلب والإسناد | `requests/request-lifecycle.ts`، `dispatch/assignment.orchestrator.ts`، `dispatch/nurse-eligibility.engine.ts` | إصدار الطلب يتحرك مع الانتقال ويتتبّع سجل الانتقالات السبب والمستخدم. الاستعادة تعيد `requests` و`assignments` و`unpaidInvoices` بحسب الدور. |
| المراجعة السريرية | `clinical-approvals/`، `pages_clinical_reviews.tsx`، `screens/track.dart` | `POST /v1/requests/:id/clinical-evidence` و`GET /v1/clinical-reviews/pending` و`GET /v1/clinical-reviews/:id/evidence` و`GET /v1/clinical-reviews/evidence/:id` و`POST /v1/clinical-reviews/:id/decision`. |
| تنفيذ الزيارة | `requests/request-items.service.ts`، `screens/service_outcomes.dart` | `POST /v1/nurse/requests/:requestId/items/:itemId/outcome`. الإكمال يتطلب نتيجة كل بند وتوثيقًا سريريًا. |
| الحسابات | `pricing/billing.service.ts`، `wallet/ledger.service.ts` | تحصيل النقد والإكرامية والتسويات تتطلب ترويسة `Idempotency-Key`. يعيد التحصيل `status` و`remaining` و`change`. تستند قراءة الفاتورة إلى `invoices`. |
| التشغيل | `marketplace/marketplace.service.ts`، `worker/src/outbox.ts`، `flutter_core/lib/src/realtime.dart` | `GET /v1/marketplace/requests` يعيد `requests` و`nextCursor`. حدث البث يحمل معرّفًا ويحفّز المصالحة عبر REST. `GET /ready` يتحقق من PostgreSQL. |

ملفات الترحيل الجديدة `052` إلى `059`. تشمل جدول انتقالات الطلب، الفواتير وبنودها والمعاملات ودليل الحسابات، جداول الموافقات والإثباتات وتدقيق الوصول، وحقول إعادة محاولة Outbox. يستخدم مُرحّل قاعدة البيانات قفل PostgreSQL واستمرّت تسمية ملفي `042` كما كانت.

## الترحيل والاستعادة

1. أثبت القدرة على استعادة نسخة كاملة من PostgreSQL ومجلد المستندات المشفّرة. احتفظ بمفتاح التشفير الحالي في إدارة الأسرار. إذا سبق اشتقاق مفتاح المستندات من JWT، يلزم ترحيل المفتاح الفعلي أو إعادة تشفير الملفات في staging قبل اعتماد مفتاح جديد.
2. شغّل `infra/db/core_stabilization_preflight.sql` على نسخة مستعادة. افحص تداخل التقويم، الحجوزات المالية المكررة، القيود غير المتوازنة، والإيصالات الصفريّة أو غير المؤكدة. اربط الطلبات المفتوحة التي تفتقد بنودًا بالبيانات الفعلية قبل فتحها للتنفيذ.
3. شغّل `node infra/db/migrate.mjs` على النسخة المستعادة. قارن أرصدة واعتمادات الإيصالات والفواتير القديمة حسب العملة، مع مطابقة عينات من السجلات العربية.
4. نفّذ ترقية الخادم والعملاء بتنسيق واحد بسبب عقود الجلسة والملفات والتحصيل. عند الحاجة إلى الاستعادة بعد ترحيل القاعدة، أوقف الكتابة، احفظ نسخة ما بعد الفشل للمصالحة، ثم استعد نسخة ما قبل الترحيل وأعد نشر البنية السابقة بعد مراجعة العمليات التي حدثت بعد النسخ.

## بوابة التحقق

| التحقق | النتيجة المحلية |
| --- | --- |
| `pnpm -r build` | نجح بناء API وWorker ولوحة الإدارة. |
| `node --test apps/api/tests/*.test.mjs apps/worker/tests/*.test.mjs` مع `TEST_DATABASE_URL` و`TEST_UPGRADE_DATABASE_URL` | 169 ناجحًا و0 فشل و0 تخطٍ. جرى اختبار الترقية في قاعدة ثانية منفصلة. |
| `core-upgrade.pg.test.mjs` على PostgreSQL 18 وPostGIS | نجحت الترقية من 051 إلى 059، وإعادة تشغيل المُرحّل، وحفظ رقم الطلب والإيصال والنص العربي وتوازن القيود على بيانات اصطناعية. |
| Flutter | 12 اختبارًا للمريض و7 للممرض و19 للحزمة المشتركة. شُغّل مسار زيارة الممرض التجريبي بتعريف `DEMO=true`، واختبارات Guardian في الإعداد العادي. بُني ملفا Android Debug. |
| HTTP محلي | أعادت `/health` و`/ready` حالة 200. نجح دخول المراجع السريري وتجديد جلسته وقراءة قائمة المراجعات، وأعادت لوحة الإدارة 403 للمراجع وقائمة المراجعات 401 عند غياب الجلسة. |
| أداء محلي استكشافي | 60 طلب كتالوج بأربعة عملاء متزامنين و25 خدمة. P95 بلغ 25.97 مللي ثانية. استخدم `EXPLAIN ANALYZE` فهرس سجل الطلبات الخاص بالمالك وكانت مدة تنفيذ الاستعلام 0.458 مللي ثانية في عينة صغيرة. |

## تغطية سيناريوهات الملحق

| السيناريوهات | الأدلة وحدودها |
| --- | --- |
| 1–3 | PostgreSQL يثبت إنشاء الطلب وإكمال الزيارة والتحصيل وفوز إسناد واحد وإعادة الإنشاء بالمفتاح نفسه. |
| 4–5 | فحوص Flutter والاستعادة وقراءة سوق مفتوح متعدد الصفحات. يلزم إثبات المسار عبر إنهاء عملية التطبيق وإعادة فتحها على جهاز فعلي. |
| 6–10 | فحوص الإلغاء والانتهاء وتقييم الأهلية والترخيص، بما فيها رفض ترخيص منتهي. لم يُحاكَ تغيير كل عامل أهلية على تطبيق فعلي أثناء قبول العرض. |
| 11–13 | اختبارات إطلاق الموعد في Worker، واختبار PostgreSQL لحجزين متجاورين ورفض تداخلهما مع احتساب فترات الانتقال. |
| 14–19 | PostgreSQL واختبارات الفوترة تثبت دمج الكمية والتوثيق والتحصيل الجزئي وإعادة الإرسال المتزامنة ومطابقة الفاتورة والدفتر. يحتاج فقد استجابة الشبكة وإعادة تشغيل التطبيق إلى تحقق على جهاز فعلي. |
| 20–23 | اختُبرت حدود الائتمان والرصيد المدفوع، وتوزيع الحجز المختلط وتحريره عند الإلغاء، وتوازن القيود في عملة العينة. لم تُنفّذ مطابقة تاريخية متعددة العملات على بيانات تشغيلية. |
| 24–25 | فُحصت قيود الدور والسياق وتدقيق القراءة، ورفض مدير غير مخول وممرض لزيارة غير مسندة إليه. لم يُعتمد مسار المراجع من متصفح متصل ببيئة التشغيل. |
| 26–29 | اختبارات Guardian لبلاغ SOS وإعادة إرسال نقاط الموقع بعد تعذر الاتصال، واختبار حجز Outbox وإعادته، ومعرّفات البث في التطبيق. لم يُنفّذ اختبار Redis وFCM واتصالات الأجهزة بتبديل ترتيب الرسائل على شبكة فعلية. |
| 30 | PostgreSQL 18 وPostGIS، مخطط جديد وترقية من 051 بزيارة وإيصال تاريخيين اصطناعيين. يتبقى تمرين الاستعادة والترقية على نسخة تشغيلية معزولة. |

يحتاج اعتماد الإصدار إلى هذه التجارب التشغيلية وقياس أداء تحت حمل ممثل، واعتماد صلاحيات Guardian والمراجعة السريرية وسياسات معالجة الأرصدة على بيانات تشغيلية. يظل شحن الأموال الحقيقية معطّلًا. راجع أيضًا تقرير [الأمان والخصوصية](security_best_practices_report.md).
