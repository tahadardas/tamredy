# خطة Sprint التالية — Phase 2

## الأولوية الأولى (لا تعمل تجاريًا دونها)
1. تنفيذ OTP + refresh token rotation + أدوار المشرفين + اعتماد الوثائق وربط صلاحية الترخيص بكل خدمة.
2. إضافة مسار قبول/إلغاء الممرض بعد الإسناد وإعادة البحث مع سجل زمني واضح وبديل تلقائي.
3. اختبارات PG حقيقية للتزامن: 1000 طلب قبول متزامن، ممرض يحاول أخذ حجزين، إلغاء متزامن، وتسويات مالية متكررة.
4. دعم FCM للأجهزة Android/iOS وتحديث اتصال Socket.IO والتعافي من الانقطاع.
5. استكمال Android/iOS platform files وGoogle Maps keys وسياسة location while-in-use/background.

## الأولوية الثانية
6. تحويل شاشات الـSRS الـ27 إلى صفحات Flutter/React مصممة ومتصلة بالـAPI.
7. بناء الحالات المعلقة والحوادث والـNo-show والاستردادات/النزاعات.
8. بناء الفواتير والقيود المزدوجة والعمولات والتسويات النقدية (دون تحويل/شحن فعلي بعد).
9. ربط محفظة مزود سوري مرخّص بعد وجود عقود رسمية وخط موافقات قانوني.
10. مراقبة العمليات والنسخ الاحتياطية والاختبار الأمني وخطة نشر staging وrollback.

## بوابة الاعتماد
- بناء NestJS وFlutter وReact دون أخطاء نوعية.
- نجاح فحوص Postgres/PostGIS/Redis/FCM على أجهزة وشبكات فعلية.
- اعتماد طبي/قانوني لكل خدمة.
- إثبات صلاحية كل عقد API واختبارات واجهات عالية التغطية.
